# Ethical Commerce — Interactive Transparency Suite (October 2026)

## What exists in staging

This builds on the *existing* seller, supplier, product, traceability and evidence platform. It does not create a separate shop or enable checkout.

| Feature | Available with limits |
| --- | --- |
| Living Supply Chain | Interactive disclosures for a real product passport; labeled fictional demo in the standards overlay |
| Money Trail | £100 hypothetical adjustable example, plus voluntary merchant-entered public/private costs by category |
| Store setup | 3-step setup with live preview; creates a real draft store using existing owner-scoped APIs |
| Product passports | Public URL, copy link, print and same-origin QR SVG for **published** products only |
| Supplier directory | Merchant can opt in individual supplier profiles; public search includes only opted-in profiles |
| Impact dashboard | Counts recorded activities, unresolved concerns and verified assessments without an ethics score |
| Launch checklist | Preparation milestones; never unlocks real payments |
| Shop | Current customer storefront UX deliberately unchanged |

## Security, ethics, consent

1. New migration: `migrations/0007_voluntary_transparency.sql`.
2. `product_money_disclosures` starts **private**. Each cost category must be explicitly opted in with `publicConsent: true` before it can appear publicly. Values are seller entered. Undisclosed portions of a price are **not assumed to be profit**.
3. Supplier directory profiles start **private**. Supplier name, country and website originate from seller records. Private risk notes, ordering emails and confidential supplier records are never exposed.
4. Only store owners/managers may write disclosures or public profiles. Signed-in store members may read owner records; third-party accounts cannot.
5. Money information is a voluntary **seller declaration, not proof of actual Stripe transfers, payouts, supplier compensation, tax compliance or independent verification**.
6. Activity metrics are not an environmental, labour-rights or ethics score. The existence of a record does not establish accuracy.
7. Public product QR codes are generated by the Worker using `qrcode-generator` under its MIT licence; private or draft products return 404. No third-party QR provider receives the passport URL.
8. Demo supplier and money values are fictional and labelled accordingly; do not reuse these to make claims about a genuine product.
9. Real money rewards, independent audits, checkout, automatic supplier ordering, inventory sync and external marketplace publishing remain gated.

## Manual test plan

**Staging URLs**
- Home: https://ethical-commerce-staging.martin-e01.workers.dev/
- Seller Studio: https://ethical-commerce-staging.martin-e01.workers.dev/dashboard
- Supplier directory: https://ethical-commerce-staging.martin-e01.workers.dev/suppliers

1. Home → Show me how → Prove the journey: scroll down and expand the example sourcing/manufacturing/transport/retail steps. Confirm the words **DEMONSTRATION** and **Missing information**.
2. Home → Make ethics rewarding: move the hypothetical basket slider. Confirm £100 example changes but promises no cash rewards.
3. Seller Studio → Money trail: choose an existing product, save an amount **without** public consent. Its public passport must not expose it. Then repeat with consent checked and verify the record appears as seller-declared.
4. Seller Studio → Supplier directory: choose an existing supplier, save description with unchecked opt-in. Search public directory: record must remain hidden. Check opt-in, save and check listing appears. Private risk notes must not be visible.
5. Seller Studio → Impact & evidence: counts reflect products, handoffs, evidence, customer concerns and opted-in disclosures, not scores.
6. For a **published** product, open its public passport, copy link, print and scan/download QR. For a draft product, QR must return 404.
7. In a new sandbox account without stores, complete the three-step creation wizard, observe preview before submission and confirm the store appears in Seller Studio.
8. Open any existing `/shop/...` route. Compare layout with the pre-change release to ensure shop styling is unchanged.
9. Verify `/api/health` and `/api/ready` return 200. Ensure health still reports payments and publishing disabled.
10. Before launch, complete end-to-end merchant Stripe Connect onboarding, signed webhook testing, refunds, independent supplier verification and approved marketplace integrations. Do not enable those because the new UI exists.

## Remaining dependencies

- Third-party supplier/catalogue/marketplace API credentials, approval, licensing and provider QA.
- Reliable stock and fulfilment automation with explicit merchant authorisation.
- Genuine audited supply-chain financial data to replace voluntary declarations.
- Defined reward programme funding, terms, fraud controls and legal assessment.
- Real merchant and consumer safety pilots; production tax/consumer compliance and performance/accessibility testing.
- Optional privacy-preserving conversion analytics and error monitoring. Don't claim these are delivered by this suite.

## Verification

CI: `npm run check`, Worker dry-run, remote-stage migration in staging deployment, local D1 and `npm run smoke`. The smoke suite checks consent isolation, public vs private disclosures, cross-tenant access, QR draft/published behavior and checkout gates.
